# 环搜索：Böhm 与 Sontacchi 判据的完备实现、完备剪枝与自算范围

（实验目录：`20-experiments/`；脚本在 `scripts/`，原始输出在 `results/`。本文件里所有数字都来自本次在本机跑出的输出，凡引用文献数字处逐条标明出处；本工作未打开文献原文，文献数字一律转引本项目的 `10-literature/notes/cycles.md` 并注明这一点。）

---

## 一、目的

三件事：

1. 把 Böhm 与 Sontacchi 的环判据（环上整数 x = c 除以（2^k − 3^m），c 由奇偶向量决定）实际实现成可跑的搜索，并做**阳性对照**：负整数上已知的三个环（含 −1、−5、−17 的那三个）必须被同一套判据全部找回来，找不回来就说明实现有 bug。
2. 长度 k 的奇偶向量有 2^k 个，稍大就无法全枚举；因此要给出**完备**的剪枝（剪掉的向量里不可能藏着任何环），并说明完备性为什么成立。
3. 如实报告本机实际做到的完备范围，并解释为什么推不到文献记录的 10^8 量级（是时间、内存，还是需要更强的丢番图工具）。

## 二、方法

### 2.1 判据与实现（`scripts/cycles_bs_enum.c`，`scripts/cycles_bs_formula_check.py`）

取加速映射 T(n) = n/2（偶）、T(n) = (3n+1)/2（奇）。设环长 k 步、其中奇数步 m 步，奇数步位置 0 = j_1 < j_2 < … < j_m ≤ k−1，环上元素满足

    x = c / (2^k − 3^m),   c = sum_{t=1..m} 3^(m−t) · 2^(j_t).

1. 2^k > 3^m 时 x > 0（正解条件）；2^k < 3^m 时 x < 0（负解）。**负环不违反判据，只是落在另一侧**，所以阳性对照只需去掉「2^k > 3^m」这条对正解的限制。
2. 2^k − 3^m 恒不为零（一奇一偶）。

实现要点（`cycles_bs_enum.c:100` 的 `leaf_test`）：从左到右扫向量，遇到 1 做 c ← 3c + 2^p（Halbeisen 与 Hungerbühler 的递推，与求和公式在 2 万个随机向量上逐位一致，见 `cycles_bs_formula_check.py`）；到叶子做整除判定 |D| ∤ c 即剪掉，c < |D| 时直接跳过（省一次除法）；命中则打印 k、m、x、c、D 与奇数步位置列表。

充分性抽检：40 万个随机向量里 54,026 个满足整除，全部通过「T^k(x) = x 且奇偶向量逐位一致」的核验（`results/cycles_bs_formula_check.txt`）。

### 2.2 完备枚举（无条件）

模式 0 遍历长度 k 的**全部** 2^k 个向量，不做任何结构性剪枝，只做叶子整除判定。它按定义完备：任何环的奇偶向量都在被遍历的集合里。

### 2.3 完备剪枝（模式 1、2、3）与完备性论证

两条剪枝，都只用无条件事实：

**剪枝 (a)（m 区间）**：任一整数环满足 0 < |k·ln2 − m·ln3| = |Σ_i ln(1 + 1/(3x_i))| ≤ Σ_i 1/(3|x_i| − 1) ≤ m/(3|x_min| − 1) ≤ m/2（最后一步用 |x_min| ≥ 1）。于是正侧 m ≥ k·ln2/(ln3 + 1/2) = 0.4336k，又正侧 2^k > 3^m 给 m < k·ln2/ln3 = 0.6309k。前缀 (p, q) 若 q + (k−p) < m_min 或 q > m_max，直接剪掉。**如实报告：这条剪枝效果可以忽略**——它只砍掉 m < 0.4336k 那一小段尾部，在 k = 28 上实测节点数只从 185 614 208 降到 185 613 926（约 0.0002%），因为向量数按 m 的分布集中在 0.5k 附近。

**剪枝 (b)（最小元定向不变式）**：把向量旋转到环的最小元处（正环最小元必为奇数；负环最小元是绝对值最大的元素）。此时每个前缀的轨迹值都是环上元素，故 x_p ≥ x_0；由 x_p = (3^q·x_0 + c_p)/2^p 得 c_p ≥ (2^p − 3^q)·x_0；正侧 x_0 ≥ 1 故 2^p > 3^q 时必有 c_p ≥ 2^p − 3^q，负侧 x_0 ≤ −1 故 3^q > 2^p 时必有 c_p ≥ 3^q − 2^p。违反的前缀剪掉。

**完备性为什么成立**：任何环的向量旋到最小元后仍是一个合法向量（第 1 步），该向量的每个前缀都满足上述不变式（第 2、3 步），所以**每个环至少留下一个不被剪的表示**；被剪掉的前缀没有任何环的旋转向量会经过它们。因此剪枝只丢非最小元定向的重复表示，不丢环本身。唯一的例外是不动点 0（x_0 = 0 违反 |x_0| ≥ 1），它由模式 0 单独找到、模式 3 漏掉，属于设计内的约定（本文档把它单列）。

### 2.4 验证界 X0 与 Y0（自算，不是引用）

判据里「环上元素都必须已被核验过」这一步需要验证界。本工作自己算了两个界：

1. X0（正侧）：凡 1 ≤ n < X0 的整数都到达 1。
2. Y0（负侧）：凡 |n| < Y0 的负整数都到达三个已知负环之一。

两种独立实现：
1. 位表法（`scripts/cycles_verify_bound.c`）：按块递增处理，块内每个 n 迭代到首次落出块外（v < 块下界 A），再查更早块已判定的表。用强归纳：n 到达 1 ⟺ 某次迭代落到 v < n 且 v 到达 1。
2. 无表法（`scripts/cycles_verify_free.c`）：对每个 n 直接迭代到首次 v < n（不需要任何表），这是把范围推大的关键。代价 = 所有 n 的 sigma(n)（首次落到自身以下所需步数）之和；本机实测均值 3.5 步（`cycles_stopping_stats`）。

保险机制：步数超上限或轨迹回到 n 自身（出现环）即记为「未判定」，程序据实把已验证范围截断到该 n 之前，不虚报。自检：两种实现互相吻合（10^10 上一致），并对 n ≤ 200000 做完整迭代对照、对全域随机抽 20000 个 n 做完整迭代对照，全部零不一致（见原始输出）。

### 2.5 Eliahou 与 Crandall 型必要条件（自推 + 常数在已知环上核验）

由环方程的乘积式 2^k = prod_i (3 + 1/x_i)（m 个因子，x_i 是环上全部奇数项）取对数：

    Lambda := k·ln2 − m·ln3 = sum_i ln(1 + 1/(3·x_i)).

正环（x_i > 0）时 Lambda > 0，负环（x_i < 0）时 Lambda < 0。用 ln(1+t) ≤ t/(1−t)（0 ≤ t < 1）得 |Lambda| ≤ Σ_i 1/(3|x_i| − 1) ≤ m/(3·X* − 1)，其中 X* = min_i |x_i| 是所有环上元素绝对值的最小者。环上元素必须逐个被核验过，于是 X* ≥ X0（正侧）或 ≥ Y0（负侧）。记 delta = log2 3、w = 1/((3·X0 − 1)·ln2)，则

    k/m − delta = Lambda/(m·ln2)，

于是得到**单侧窗口**：

1. 正环：0 < k/m − delta ≤ w，等价于 1 − frac(m·delta) ≤ m·w；
2. 负环：−w ≤ k/m − delta < 0，等价于 frac(m·delta) ≤ m·w。

排除规则（这就是剪枝在 (k, m) 平面上的形式，比逐向量剪枝强得多）：

1. 「奇数步数为 m 的正环」被排除 ⟺ 1 − frac(m·delta) > m·w；
2. 「奇数步数为 m 的负环」被排除 ⟺ frac(m·delta) > m·w。

记 M+ = 使 m = 1..M+ 全部被正侧排除的最大 M+（M− 同理）。

**这两条排除都带前提**：只适用于**环上每个元素都被核验过**的环，即正侧 |x_i| ≥ X0、负侧 |x_i| ≥ Y0。已知的五个环（{0}、{1, 2}、{−1}、{−5, −7, −10}、{−17 族}）的元素绝对值最大只有 136，全部落在前提之外，因此不受这些排除约束——这正是判据能与已知环并存、不产生矛盾的原因。对满足前提的环，因为任何环满足 k ≥ m（奇数步数不超过总步数，负环 {−1} 取等号），所以「不存在 m ≤ M 的环」蕴含「不存在周期 ≤ M 的环」。下文各处引用 M+、M− 时一律默认带上这条前提。

**这个剪枝的完备性**：它是必要条件（每个环都必须满足），没有任何环能绕过它；它排除的是整个 (k, m) 参数对，而不是个别向量。与 §2.3 的逐向量剪枝相比，它把「2^k 个向量」换成「先排除整片 (k, m)，剩下的再谈」，这是本工作把范围推大的关键。

常数核验（`scripts/cycles_criterion.py`）：四个已知环全部满足该不等式（最紧的是负环 {−5,−7,−10}，比值 0.82）；枚举搜索找到的全部 134 条真实环解（不含不动点 0）也全部满足，零违反。

本工作的判据在三个档上都更强，方向合理：引理形式只取收敛项 q_n 并带较松的常数，本工作用到半收敛项分母与单侧窗口（正环只走「k/m > delta」一侧，负环只走另一侧）。脚本：`scripts/cycles_crandall_crosscheck.py`，输出 `results/cycles_crandall_crosscheck.txt`。

**对照二（台阶坐标的对应，可作判据强度的独立旁证）**：本工作判据在 X0 = 10^12 时的首个未排除 m 是 10 781 274，恰是 delta = log2 3 的第 15 个收敛项**分母** q_15；而文献里 Eliahou 判别法在验证到 2^40 = 1 099 511 627 776 时给出周期下界 17 087 915，恰是同一收敛项的**分子** p_15。两者满足 p_15 ≈ delta·q_15（复算 δ·10 781 274 = 17 087 914.99999998，见 `results/cycles_convergent_correspondence.txt`）。因为正环满足 k·ln2 > m·ln3 即 k > δ·m，本工作在前提（环上元素绝对值至少 X0 = 10^12）下的结论「m ≥ 10 781 274」蕴含 k > 17 087 914.99999998，也就是 **k ≥ 17 087 915**，与文献那条逐位相同（文献那条同样只针对非平凡环）。两条判据跨过同一台阶所需的验证界也几乎相同：本工作 9.84573 × 10^11，文献 2^40 = 1.099511627776 × 10^12；按同一分母复算（`results/cycles_review_check.txt`）：**文献门槛比本工作高 11.674%**，等价地**本工作比文献低 10.454%**。这是对判据强度的独立旁证：它落在文献判别法的同一量级上，而不是差几个数量级。

## 六、为什么推不到文献记录的 10^8 量级

先把「10^8 量级」在本项目的文献笔记里对应什么写清楚（以下三条都是**转引**本项目的 `10-literature/notes/cycles.md`，我没有打开这些文献原文）：

1. Eliahou（1993，Discrete Mathematics 118）在「验证到 2^40」的输入下给出非平凡环长下界 17 087 915（约 1.7 × 10^7）（cycles.md 第 5 条；该条标注原文未打开，数字经 Halbeisen 与 Hungerbühler 1997 与检索片段互证）。
2. Halbeisen 与 Hungerbühler（1997，Acta Arithmetica 78）用改进判别法，把门槛换到「验证到 212 366 032 807 211（约 2^47.6）」时环长下界跳到 102 225 496（约 10^8）（cycles.md 第 4、7 条；该条我读了 PDF，是笔记作者的核对结论）。
3. 当前记录：加速映射下周期至少 217 976 794 617，标准映射下至少 355 504 839 929（cycles.md 第 16 条，含出处缺口说明），机制是 Hercher 2023 的自举机具（K > q_23 = 137 528 045 312）叠加 Barina 2025 的验证界 2^71。

三条障碍，逐条对应本机实测：

1. **奇偶向量枚举这条路是 2^k，不可能到 10^8。** 本机实测：k ≤ 34 全枚举（3.44 × 10^10 个叶子）用 70.2 秒，即约 4.9 × 10^8 个叶子每秒；k = 40 需约 37 分钟，k = 50 需约 26 天，k = 10^8 无论时间还是内存都差天文数字。完备剪枝（最小元定向不变式）只砍掉多项式比例（实测 3 倍），改不了指数。想用时间与空间折中（meet in the middle）也至少要 2^(k/2) 个状态的哈希，10^8 的 k 同样不可能。
2. **「验证界 + 必要条件」这条路是本工作真正走通的，代价由连分数台阶决定。** 判据给出的排除上界大约随 sqrt(X0) 增长，但带连分数台阶（台阶之间几乎不涨）：X0 = 10^11 给 1.9 × 10^5，X0 = 10^12 给 1.08 × 10^7，而要 m ≥ 10^8 需要 X0 > 2.46 × 10^15，**中间 10^13 到 10^15 这几档的 m 上界几乎不涨**（这正是「台阶」的含义）。按本机实测速率（10^12 档：正侧 10^12 个整数用 4815.8 秒 = 2.08 × 10^8 个每秒，负侧 1.83 × 10^8 个每秒；10^11 档分别 1.54 × 10^8 与 2.52 × 10^8 个每秒），10^15 档的验证需要约 1.2 × 10^7 至 1.6 × 10^7 秒，即约 140 至 190 天（时间墙）；若改用位表法则是 2.46 × 10^15 bit ≈ 300 TB（内存墙，本机 8 GiB）。本机 8 GiB 内存是硬约束，这也是我把位表法换成无表法的原因。
3. **跨过 sqrt 台阶需要更强的判别法（在丢番图一侧），本工作没有用。** 上面的排除只用到「乘积式 + 连分数/单侧窗口」这一层初等工具；文献里 10^8 量级的一档（验证到约 2^47.6 得 102 225 496）用的是 Eliahou 判别法与 Halbeisen 与 Hungerbühler 的改进版，当前记录（10^11 量级）用的是 Hercher 的自举（反复把 K 下界抬到新的连分数门槛，直至与 Simons 与 de Weger 的上界相交）。这类工具在文献里还要接上显式对数线性型下界（Simons 与 de Weger 用 Rhin 1987；一般形式用 Laurent、Mignotte、Nesterenko 1995 与 Matveev）——那是需要专门本领的丢番图工具，本工作既未实现也未使用，所以差距不只是算力。

一句话：**本机做到的是「无条件周期 ≤ 34（完整枚举）」与「在自算验证界 10^12 下，已知五个环之外、元素绝对值至少 10^12 的环周期 ≥ 17 087 915（必要条件排除）」两档；10^8 那一档卡在验证界的算力（约 140 至 190 天，或位表法需要的 300 TB 内存）与判别法强度（需要 Hercher 式自举与显式对数线性型下界），不是靠多跑几小时能补上的。**

## 七、这个实验不能证明什么

1. **不能证明科拉茨猜想，也不能证明「没有非平凡正环」。** 本实验的全部结论都是**有范围限制的**，而且判据那两条还带「环上元素绝对值至少 10^12、已知五个环除外」的前提：完整枚举只覆盖周期 ≤ 34（无条件）；判据只说明「元素绝对值至少 10^12 的正环周期至少 17 087 915」与「元素绝对值至少 10^12 的环奇数步数至少 5 446 238」这两条（依赖我自算的验证界 10^12）。这些范围之外，本实验对环的存在性一无所知；尤其对「是否存在任何非平凡正环」没有任何结论；已知五个环的存在也与判据毫无冲突。
2. **判据一档的结论依赖我自算的验证界，而验证界本身没有被形式化验证。** X0 = Y0 = 10^12 都是我在本机算出来的。实现正确性的旁证有三层：两种独立实现在 10^10 上给出同一结论；各档都有 20 万次完整迭代对照；位表法导出的前 10^6 项与 Python 逐项完整迭代零不一致。但 10^11 与 10^12 两档只有无表法一种实现跑过，「无表法在大范围上仍有系统错误」这一可能本实验无法排除；这也不是机器证明。
3. **排除判据的数值比较用的是 60 位与 200 位浮点，而不是区间算术或严格连分数界。** 我做了稳定性检查（两个精度下 M+、M− 完全一致，且最小余量 > 1.2，即离判定边界不近），但没有给出可机检的严格证书；本机也没有形式化工具链（Lean、Coq 均未安装，见 `ENV.md` 第五节实测）。因此「M+ = 10 781 273」这一数字的严格性弱于一条定理，强于一次随手估算。
4. **剪枝的完备性有前提，且有一个设计内例外。** 最小元定向不变式的完备性依赖 |x_0| ≥ 1，因此剪枝模式漏掉不动点 0（模式 0 找到它）；判据一档依赖「环上每个元素都被核验过」：正侧依赖我在 10^12 内验证到 1 的事实，负侧依赖「凡 |n| < 10^12 的负整数都到达三个已知负环之一」这一同样由我验证的事实。
5. **本实验不能判断负环的穷尽性。** 「整数上除 0、1 与三个负环外没有别的环」是文献里的猜想（cycles.md 第 118 行记为 Böhm 与 Sontacchi 的猜想、未证）；本实验只给出两个有限范围的旁证（|n| < 10^12 的负整数都到达三个已知环；三个已知负环之外的新负环（元素绝对值至少 10^12）奇数步数必须至少 5 446 238），不能支持或反驳该猜想。
6. **性能数字只对本机本实现成立。** 「无表法每秒约 1.5 × 10^8 个整数」「剪枝模式 1.18 × 10^8 节点每秒、穷举模式 1.29 × 10^9 节点每秒」等实测值受 macOS 的后台调度影响很大：同一条 `cycles_bs_enum 0 34` 命令在后台调度下用了 656 秒，前台只用 70.2 秒（相差 9 倍）。因此文中所有「需要多久」的推算都是量级估计，不是承诺。
7. **本文不构成对文献数字的独立复核。** 17 087 915、102 225 496、217 976 794 617 等数字全部转引本项目文献笔记，我没有打开 Eliahou 1993、Simons 2005 等原文，也没有重跑文献的计算；我对它们的使用仅限于「量级对照」。
