## 一、目的

按任务给定的分支规则，从 1 出发做广度优先生长，测定三件事：

1. **节点数随层数的增长曲线**，并与 `(4/3)^层数` 这类预测对照；
2. **每层覆盖了哪些奇数**；
3. **在小范围内，是否每个奇数都出现在树里**。

任务同时给出一条纪律，本实验全程遵守：**树包含所有奇数与原猜想等价**，因此小范围内的成功只是阳性对照，不是证明路径的近似。第五节把这个限制逐条写清。

## 二、方法

### 2.1 分支规则（严格照任务原文）

节点 `x` 的两个孩子是：

1. `2x`，永远可用；
2. `(2x-1)/3`，仅当 `2x-1` 是 3 的倍数、且 `(2x-1)/3` 为正奇数。

代码位置：`scripts/reverse_tree_bfs.py:29` 至 `scripts/reverse_tree_bfs.py:36`（Python 版），`scripts/reverse_tree_deep.c` 的生成循环（C 版）。

### 2.2 两条先行的结构性事实（本实验都做了计算核对，不是引用文献）

**事实 A：第二个条件「结果为正奇数」是冗余的。**
`3 | (2x-1)` 等价于 `x ≡ 2 (mod 3)`；此时写 `x = 3k+2`，则 `(2x-1)/3 = 2k+1`，自动是奇数。也就是说第二个分支的可用条件实际就是 `x ≡ 2 (mod 3)`。
核对：Python 版检查项 `second_branch_auto_odd`＝成立；检查项 `second_child_iff_x_eq_2_mod_3`＝成立（即「第二个孩子存在」当且仅当 `x ≡ 2 (mod 3)`）。

**事实 B：每个节点的父节点唯一，所以这是一棵真树。**
按任务的分支反解父节点：偶 `n` 的父是 `n/2`；奇 `n` 的父是 `(3n+1)/2`。两个公式在奇偶意义上互斥且各自单值，故每个非根节点的父节点唯一。于是：

1. 广度优先的各层互不相交，且**第 d 层恰好是 `{n : σ(n) = d}`**，其中 `σ` 是「偶除以 2、奇取 `(3n+1)/2`」这条短路映射的总停时（从 `n` 走到 1 的步数）。
2. 「`n` 出现在树里」等价于「`n` 的前向轨道回到 1」。
3. 因此「树包含所有奇数」等价于「每个奇数的轨道回到 1」；又因偶数 `n = 2^k · m`（`m` 奇）走 `k` 步即到 `m`，这等价于原猜想。
4. 全树唯一的例外是 `2` 的第二个孩子是 `1`（即根），广度优先去重时会跳过它一次。

核对：Python 版 4.1 父映射一致（违规 0 个）、4.4 重复孩子事件共 1 次且恰为 `[(2, 1)]`。

### 2.3 两套互相独立的实现

1. **Python 版** `scripts/reverse_tree_bfs.py`：带全局 `seen` 集合的朴素广度优先，逐层记录节点数、奇偶个数、模 3 分布、孩子数；对全树做四项结构校验；另算一张 `n <= 10^6` 的前向停时表并与层号双向比对。
2. **C 版** `scripts/reverse_tree_deep.c`：因为各层互不相交（事实 B），只需同时保存**当前层与下一层两个数组**，不需要全局哈希表，因此能把深度推到 Python 到不了的地方。元素类型是 `unsigned __int128`（`sizeof` 实测 16 字节），因为第 65 层的最大节点是 `2^65 = 36893488147419103232`，已超出 64 位。每一层做两项校验：(a) 层内严格递增（层内无重复）；(b) 每个孩子的父节点按前向公式（从孩子反算，不查生成时的记账）反算后，能在上一层里二分查到。两项合起来，用归纳法即得各层恰是精确的广度优先层且互不相交。
3. **分析与交叉校验** `scripts/reverse_tree_analysis.py`：读两版输出，逐字段比对；算 `σ` 表；算「深度 D 的树完整覆盖到哪个奇数」；核对结构性恒等式「第 d+1 层奇数个数 = 第 d 层中 `x ≡ 2 (mod 3)` 的个数」。

### 2.4 覆盖性的判定方式（两条路，互相独立）

1. **显式建树**：把树长到深度 D，检查哪些奇数落进了这 D 层。
2. **前向轨道**：独立算出每个奇数 `n` 的停时 `σ(n)`（方法与建树完全无关），由事实 B，「`n` 在树里」等价于「`σ(n)` 有限」，且出现的深度就是 `σ(n)`。

两条路在重叠部分必须一致，这一点在下文第五节第 6 条给出核对结果。

### 3.1 规模为什么停在这里（如实报告降级）

1. **C 版请求深度 66，主运行实际到达 65；直接原因是程序自己的内存保护偏保守，而不是第 66 层真的放不下。** 程序在生成下一层前用 `need = N(d) × 1.45 + 1024` 预估容量，按这个粗估，生成第 66 层「要」128,631,046 个元素（每个 16 字节）＝ 2.06 GB，超过我设的 2.0 GB 阈值，于是打印
   `[内存保护] 下一层预计需要 2.06 GB，超过阈值 2.0 GB，停在深度 65。`（见 `results/revtree_c_deep.txt:160`）并停止。
   但 2.06 GB 只是粗估。由本实验逐层核对过的恒等式（第 d+1 层比第 d 层多的节点数，等于第 d 层中 `x ≡ 2 (mod 3)` 的个数），第 66 层的真实规模是
   `N(66) = 88,710,360 + 29,570,329 = 118,280,689`，即 1,892,491,024 字节 ＝ **1.89 GB**，其实低于 2.0 GB 阈值（粗估比真实需求多 8.75%）。
   这一点已用实跑坐实：把阈值放宽到 2.1 GB 补跑一次（`results/revtree_c_d66.txt`），程序确实推进到第 66 层，**实测 `N(66) = 118,280,689`**，与恒等式的预测逐位一致；该次运行峰值内存 3.31 GB、耗时 397.02 s、校验仍为 `verify_fail = 0`。同时实测第 66 层中 `x ≡ 2 (mod 3)` 的个数为 39,424,846，故 `N(67) = 118,280,689 + 39,424,846 = 157,705,535`，换算 2.52 GB，这才真正超过 2.0 GB 阈值。
   核对脚本：`scripts/reverse_tree_recheck.py`，输出 `results/revtree_recheck.txt`。
2. **为什么不把阈值调高。** 本机总内存 8 GiB；最深一步已经同时驻留两个数组，实测 peak memory footprint 2.49 GB。按实测常数外推，第 70 层单层就有约 3.74e8 个节点，仅一个数组就要 5.98 GB，加上相邻层会超出安全范围。
3. **而且再往下换来的覆盖率增长是可算的，而且很少。** 覆盖上界 `M(D)`（使所有奇数 `n <= M` 的停时都不超过 D 的最大 M）可以用前向停时表精确算出（`results/revtree_recheck.txt`）：

   | 深度 D | 25 至 69 | 70 | 71 至 72 | 73 至 74 | 75 |
   |---|---|---|---|---|---|
   | 完整覆盖上界 M(D) | 25 | 53 | 71 | 95 | 127 |
   | 该深度外最小的奇数 | 27（停时 70） | 55（停时 71） | 73（停时 73） | 97（停时 75） | 129（停时 77） |

   也就是说：把深度从 65 推到 70 才能让 `27` 进树，而覆盖上界只从 25 升到 53；推到 75 才升到 127。代价这边：按实测常数外推，第 70 层单层约 3.74e8 个节点，仅一个 16 字节数组就要 5.98 GB。
   结论（定性判断不受影响）：**显式建树在覆盖性上极不划算**，多花近十倍内存，换来的完整覆盖范围仍然只有两位数到三位数。
   （修订说明：本节初稿写的是「把覆盖上界从 25 推进到 27 需要深度 70，即使冒险建成，上界也只从 25 挪到 27」，那是错的：`M(70)` 不是 27 而是 53，因为 27 到 53 之间的奇数停时都不超过 70。复核员指出后已改正，见 7.3。）
4. **Python 版的 48 层是我选定的，不是被程序截断。** 它在 48 层的实测峰值是 506 MB（累计 2,667,068 个节点）；Python 的每节点开销远高于 C，按同一口径外推，55 层会到数 GB 量级。所以 Python 版的任务是「带全套结构校验并与 C 版逐字段互证」，深度交给 C 版去推。

### 4.3 结构性恒等式（意外收获，已逐层核对）

第 `d+1` 层的奇数个数，恰好等于第 `d` 层中 `x ≡ 2 (mod 3)` 的节点个数。逐层核对 d = 0 至 64，**唯一例外是 d = 1**：第 1 层只有节点 2（`2 ≡ 2 mod 3`），它的第二个孩子是 1（根），按去重规则被跳过，于是第 2 层奇数个数是 0 而不是 1；d = 2 至 64 全部成立，无例外。例：第 64 层 `x ≡ 2 (mod 3)` 的个数 = 22178988，第 65 层的奇数个数 = 22178988。

理由也是初等的：第 d 层的孩子只有 `2x`（偶）与 `(2x-1)/3`（当 `x ≡ 2 mod 3`，必为奇）两类，两类按奇偶性不相交，`x ↦ (2x-1)/3` 单射，且层内无重复（本实验已校验）。据此，如果「`≡2 (mod 3)` 的密度趋于 1/3」与「层增长比趋于 4/3」这两条实测趋势在更大深度继续成立，则奇数占比的极限应为 `(1/3)/(4/3) = 1/4`；这句是由实测趋势作的**推断**，不是证明。实测第 65 层为 0.250016。

### 4.4 覆盖性（两条独立的路）

显式建树这一路：

1. 深度 48 的树：完整覆盖全部奇数到 `n = 25`；
2. 深度 65 的树：完整覆盖全部奇数到 `n = 25`；
3. 深度 65 之内**尚未出现的最小奇数是 27**，它的出现深度是 70。

前向轨道这一路（与建树无关）：

1. 奇数 `n <= 1,000,000`（共 500,000 个）**全部**的轨道回到 1，无一例外（这一条由前向迭代直接验证，与建树无关）；按第 2.2 节事实 B 的等价关系，它们都在这棵（无限深的）树里。这个等价关系在重叠部分做过双向核对（`n <= 10^6` 且停时不超过 48 的那些奇数），但「停时大于 48 的奇数也在树里」这一步用的是结构论证，不是逐点造出来的树节点；
2. 停时 `σ` 的最大值 329（在 `n = 837799`），奇数上的平均停时 91.6065；
3. 完整覆盖奇数 `n <= M` 所需的最小深度：M = 25 需深度 16；M = 100 需 75（由 97 达到）；M = 1000 需 113（由 871 达到）；M = 10000 需 165（由 6171 达到）；M = 100000 需 221（由 77031 达到）；M = 1000000 需 329（由 837799 达到）。

两条路的交叉核对：在 `n <= 10^6` 范围内，深度 48 的树**包含**的节点与「`σ(n) <= 48`」的集合**完全相同**（树中有而停时表判无 0 个，停时表判有而树中无 0 个）；树中每个 `n <= 10^6` 的节点的层号与该节点的 `σ(n)` 逐个相等（不一致 0 个）。

## 六、这个实验不能证明什么

1. **小范围的成功不是证明路径的近似。** 树包含所有奇数与原猜想等价（第 2.2 节事实 B 第三条），而本实验只展开了一个有限片段：深度 65、3.548 亿个节点，**完整覆盖的奇数只到 `n = 25`**。从 `n = 27` 起这条路线不再给出任何完整性保证：27 本身就不在深度 65 的树里，而 `n <= 200` 内共有 22 个奇数缺席（27、31、41、47、55、63、73、83、95、97、109、125、129、143、145、147、165、171、189、193、195、199）；树里虽然也出现了不少大于 25 的奇数，但那是零散的收纳，不是成段的覆盖。阳性对照的意义仅在于「这条实现路线在有限范围内不出错」，不是「猜想在此被部分验证」。
2. **关于无限情形的一切断言都没有得到支持。** 本实验没有证明任何奇数的轨道一定回到 1，也没有排除某个奇数轨道发散或落进非平凡环，因为这两种情形在有限范围内不可见。前向轨道的验证同样只到 `n <= 10^6`：这个范围之外的奇数，本实验一个都没查。
3. **「增长率是 4/3」只是 65 层内的经验事实。** 实测比值 1.333347 与 `4/3` 的吻合（相对差 +0.0010%）不能推出极限成长率就是 `4/3`；实测常数 0.671338 也没有被证明收敛，它可能在更大深度缓慢漂移。同理，`d = 113` 时「约 `8.8e13` 个节点」是线性外推，不是测量值，本机根本没有建到那一层。
4. **本实验没有给出任何关于「所有奇数」的论证。** 所有结构性陈述（父节点唯一、层 = `σ` 的纤维、树含所有奇数等价于猜想）在这里是初等推理加有限核对的组合（核对范围：48 层与 `n <= 10^6`），既不是形式化证明，也没有覆盖到无限多个节点。
5. **与 `(4/3)^d` 的对照不含文献复核。** 常数 0.6713 是本机实测值；本实验没有核对任何文献里的渐近常数或误差项，因此它不构成对文献结论的验证，也不构成反驳。
6. **两条独立路径的一致不能排除共同的建模错误。** 前向停时表与建树两法共用同一套分支定义与同一个「父节点唯一」的推理；如果这条推理本身有错，两法会一起错。本实验做了代码层面的独立实现（Python 与 C 两套），但两套都建立在这一个结构论证上。

### 7.3 复核与修订记录（2026 年 10 月 19 日）

复核员用另一套方法核对本报告后提出四点，逐条处理如下。前三点的结论是**复核员正确、原报告有误**，均已改正；第四点是复核员如实声明的「未复核项」，不是错误。

1. **第 66 层的规模（原 §3.1 第 1 条）——我的错。** 原报告把内存保护公式的粗估（`N(65) × 1.45 + 1024 = 128,631,046` 个元素 ＝ 2.06 GB）说成了「生成第 66 层预估需要」的内存，读者会误以为第 66 层真的放不下。复核员独立算出 `N(66) = 118,280,689`（1.89 GB），低于阈值。我用两条互相独立的路验证了复核员的数：一是恒等式 `N(66) = N(65) + 第 65 层中 x ≡ 2 (mod 3) 的个数 = 88,710,360 + 29,570,329 = 118,280,689`；二是实跑（阈值放宽到 2.1 GB，`results/revtree_c_d66.txt`）**实测 `N(66) = 118,280,689`**，与预测逐位一致，并实测第 66 层中 `x ≡ 2 (mod 3)` 的个数为 39,424,846，故 `N(67) = 157,705,535`（2.52 GB）——复核员的这两个数也都被我复现。修订：§3.1 第 1 条已改写，明确区分「粗估」与「真实规模」，并补上补跑的实测值。
2. **深度 70 的覆盖上界（原 §3.1 第 3 条）——我的错。** 原报告写「把覆盖上界从 25 推进到 27 需要深度 70」。这是把「27 首次出现的深度是 70」误当成「深度 70 的覆盖上界是 27」。用本实验自己算出的停时表重算：`σ(27) = 70`、`σ(31) = 67`、`σ(41) = 69`、`σ(47) = 66`、`σ(53) = 9`、`σ(55) = 71`，故深度 70 内 27 到 53 之间的奇数全部出现，`M(70) = 53`，第一个缺席的是 55。复核员的数字完全正确。修订：§3.1 第 3 条换成 `M(D)` 表（`M(70) = 53`、`M(71) = 71`、`M(73) = 95`、`M(75) = 127`），并保留原定性结论（显式建树极不划算）。
