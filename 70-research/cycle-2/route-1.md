## 二、证明骨架（编号步骤，逐步标注证据类型）

记 `p_j/q_j` 为 `δ` 的连分数收敛子，`γ := [a_0; a_1, …, a_41, 2]`（`a_j` 为 δ 的部分商）。

**引理 G（已证，本路线自证，4 行）**：若 `p/q < p'/q'` 且 `p'q − p q' = 1`，则任一满足 `p/q < r/s < p'/q'` 的有理数 `r/s` 有 `s ≥ q + q'`。
证明：令 `u := rq − ps`，由 `r/s > p/q` 与 `s,q > 0` 得 `u > 0`，而 `u` 为整数，故 `u ≥ 1`；同理由 `r/s < p'/q'` 得 `w := p's − rq' ≥ 1`。于是 `q'u + qw ≥ q' + q`，而恒等式 `q'u + qw = s·(p'q − pq') = s` 给出 `s ≥ q + q'`。□

**引理 H（已证，标准恒等式，本路线逐项实算核对）**：`p_j q_{j−1} − p_{j−1} q_j = ±1`；且对本格的末段 `a_42 = a_43 = 1` 使 `q_43 = 2 q_41 + q_40`。

**步骤 1（已证）**：`δ ∈ [dlo, dhi]`，`dhi − dlo = 7.77549809×10⁻³⁸⁶`。做法：`ln2` 用 `2·atanh(1/3)` 级数与显式尾界，`ln3 = ln2 + ln(3/2)` 而 `ln(3/2) = 2·atanh(1/5)`，两段尾界都是初等可验的几何级数估计，全部 `Fraction` 精确算术。

**步骤 2（已证）**：由步骤 1 的区间做连分数区间递归（每步用 `floor(lo) = floor(hi)` 判定，尾取倒数并把区间反向），得 `a_0 … a_47`，且与 materials.md:166 记录的 mpmath 值前 46 项逐项一致。

**步骤 3（已证）**：`γ = p_43/q_43 = 325919355854421968365/205632218873398596256`，分母 = `K*`（精确整数恒等式 `2q_41 + q_40 = q_43 = K*`）。

**步骤 4（已证）**：两对邻接：`|p_43 q_42 − p_42 q_43| = 1`、`(3p_41 + p_40)·q_43 − p_43·(3q_41 + q_40) = 1`（精确整数）。故 `(p_42/q_42, p_43/q_43)` 与 `(p_43/q_43, [P,3])` 都是引理 G 可用的邻接对，其中 `[P,3] = (3p_41+p_40)/(3q_41+q_40)`。

**步骤 5（实跑已证）**：`p_42/q_42 < dlo`（差 `−3.738590×10⁻⁴¹`）且 `γ > dhi`（差 `+6.244680×10⁻⁴³`）。于是 `p_42/q_42 < δ < γ`。

**步骤 6（实跑已证）**：可行性分类（精确有理区间比较，余量都不是临界）：
`G(91) ≤ (91/92)·K*`（比值下界 1.0654330652）成立，故 `m2 = 91` 可行；
`G(92) > K*`（比值下界 1.4714529693）成立，故 `m2 = 92` 不可行。
由 Theorem 21 的假设 `m2 ≤ m = 92`，可行集 ⊆ {1, …, 91}。

**步骤 7（实跑已证）**：`ε_opt(K*) ∈ [E_lo, E_hi]`，其中
`E_lo := (3/X0)/(3·K*·ln2_hi) = 8.755860480644673357335956527977×10⁻⁴²`，
`E_hi :=` `ε(91, K*)` 的上界 `= 8.973221708617136016325724785544×10⁻⁴²`。
上半：由步骤 6，`m2 = 91` 可行，故 `ε_opt ≤ ε(91, K*) ≤ E_hi`（论文链条读法 `max_feasible` 在本格也只能取 91，因为 92 不可行）。下半：对 `m2 ∈ [1, 91]` 有 `A(m2) ≥ 3/X0`（`m2 = 91` 取等；`m2 ≤ 90` 时 `A ≥ 267/(54X0)`，若按论文证明末行的 `+1` 口径则为 `195/(54X0)`，两种口径都 `> 162/(54X0)`），故每个可行 `m2` 的 `ε ≥ A(m2)/(3K*·ln2) ≥ E_lo`。**这一半不需要 `2^v − 1` 与 `(2^v−1)^δ` 的任何界**，只需 `ln2` 的一个严格上界。

**步骤 8（实跑已证）**：`γ ∈ (δ, δ + ε_opt(K*))`：
`γ − δ ∈ [γ − dhi, γ − dlo]`，严格下界 `6.244680669692735665906111668498382045809483039×10⁻⁴³ > 0`；
`(δ + ε_opt) − γ ≥ dlo + E_lo − γ = 8.131392413675399790745345361127236002902833657×10⁻⁴² > 0`。

**步骤 9（实跑已证）**：`[P,3] > δ + ε_opt(K*)`：用 `dhi + E_hi` 的精确有理比较，余量 `> 8.81550136×10⁻⁴²`。

**步骤 10（已证，收口）**：取任一有理数 `r ∈ (δ, δ + ε_opt(K*))`：
1. `r < γ` 时 `r ∈ (p_42/q_42, p_43/q_43)`（步骤 5），由引理 G 得 `s ≥ q_42 + q_43 = 333572320386860603109 > K*`；
2. `r = γ` 时分母恰为 `q_43 = K*`（步骤 3）；
3. `r > γ` 时 `r < δ + ε_opt < [P,3]`（步骤 9），故 `r ∈ (γ, [P,3])`，由引理 G 得 `s ≥ q_43 + (3q_41 + q_40) = 488956555106733781915 > K*`。
故区间内不存在分母小于 `K*` 的有理数，而 `γ` 在其中且分母为 `K*`，于是最小分母恰为 `K*`。**陈述 C 得证。**□

### 4.4 锚点自检的设计（为什么这几条能抓错）

1. `2^δ ∋ 3`：把步骤 1 的 δ 区间喂给 `2^x` 例程必须包住 3（因 `2^δ = 3` 是 δ 的定义式）。这一条同时检查了 `ln2` 界、`ln3` 界、δ 的比值、`exp` 级数、`2^x` 的整数部分拆分整条链。
2. `exp(ln2) ∋ 2`、`exp(ln3) ∋ 3`：`ln` 与 `exp` 的互逆自检（两条独立实现路径）。
3. `ln` 的归约路径与 `ln3` 的级数路径必须相交。

## 六、失败点清单（本轮踩到的与必须点出的）

1. **严格有理区间链会被端点分母炸掉**：`δ^91` 的端点分母上万位，直接进 `exp`／`ln` 级数会把分母撑到百万位，首次跑法 90 秒不出结果（已实测卡死）。修法是每一步做 `10⁻²⁰⁰` 定向舍入。**这是本路线真正的工程瓶颈**，若有人接手必须保留这一步。
2. **钉住值不能做区间包含判定**：`materials.md` 与项目里钉住的 `δ`、`c`、`ε`、`v` 都是截断或舍入到自身位数的十进制，而本库区间宽 `10⁻³⁸⁶` 量级，包含判定必然 `False`。故锚点自检只能写成「截断位数一致」或「差 < 该位数允许的误差」。本会话亲自复现了 `r4x_rig.py:62` 的 `False` 与 `materials.md:362` 第 1 条登记的成因（截断值严格小于 `δ`，落在宽度 `1.8×10⁻²⁴⁴` 的区间之外）。
3. **materials.md:195 的公式与其自身数字不符**：该行写 `A(91) = 170/(54·X0)`，但同一行给的数字 `3.7440075021082167505×10⁻²¹` 等于 `3/X0`（本会话实测：`3/X0 = 3.744007502108216750529333×10⁻²¹`，而 `170/(54X0) = 3.928896761471585478950535×10⁻²¹`）。**应为 `3/X0`**（印出版 Theorem 21 的 `m2 = m−1` 特例，`/tmp/h5.txt:713` 至 `:718` 逐字核对；`r4x_core.py:92` 至 `:97` 的实现也是 `3/X0`）。本证书用的是 `3/X0`，且该行 97.6% 的读数不受影响（数字本身是对的）。
4. **`+1` 与 `+73` 的印出版矛盾对本证书无影响**：`m2 ≤ m−2` 时 `A` 的最小值在两种口径下分别是 `195/(54X0)`、`267/(54X0)`，都大于 `m2 = m−1` 处的 `162/(54X0)`，故步骤 7 的下界不需要裁决该矛盾。
5. **本路线的全称性只覆盖一个点**：证书证明的是 `K = K*` 这一个 (实) 阈值处的判定；把它升到区间或升到「整个起点类」需要 `Ψ` 的非降性（引用）或别的论证。**有限点的严格证书只证那一个点**（learnings.md:14 的纪律）。
6. **未做的负向检验**：本轮没有做「改一个参数看证书是否失败」的扰动检验（例如把 `K*` 换成 `K* ± 1` 看 `[C8]/[H2]` 类判据会不会翻），因此无法排除「判据恒真」这类实现错误。**这是我建议的下一步**（见第八节）。
7. **`route1_extra.py` 跑通版里有一条硬编码占位判据（已披露、已修补、已单点补核）**：该脚本首次跑通（用时 2503.3 秒）的版本里 `[J3]` 写成 `ck(..., True, ...)`，即它**不做计算就为真**——这类判据不可证伪，属实现缺陷。它的实质内容是「`m2 = 92` 在 `[Ka, Kb]` 与 `K₂` 上可行」，本会话用独立脚本 `route1_k2feas.py` 重算（`G(92)` 的严格上界 `3.0257813904697416943295316×10²⁰ ≤ Ka`，余量 `1.06×10¹⁹`，判据 `[M1]`、`[M2]` 为 True，用时 30.3 秒，退出码 0），并把脚本源文件里的 `[J3]` 改成真计算。**改动后的 `route1_extra.py` 未重跑**（一次要 41.7 分钟），故报告里 `route1_extra.out` 的数字来自跑通版，而该文件的现行 md5 对应的是改后版本。
8. **一处判据阈值写错并当场自捉**：`route1_k2feas.py` 第一次运行时 `[M6]` 要求「余量 > 10⁻⁶⁰」而实算余量是 `6.517429486498636248973948493877470980557583180×10⁻⁶²`，于是判 False。**错的是阈值不是数学**：该余量的正性才是结论所需，已把判据改为「余量为正」并重跑（全 True）。这条与本报告要强调的纪律同源：判据必须写成能失败的形式，且阈值必须来自推导而不是凑数。
